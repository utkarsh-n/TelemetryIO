# Telemetry I/O capability map

Checked 2026-10-11 against official Apple documentation, the installed iPhoneOS 27.0 SDK, and the current Spectra/Gyre sources. API availability is separate from actual device support, permission, entitlement, a connected peer, and receipt of a usable sample. This is the implementation inventory; a listed public API is not a claim that the first app version has implemented it.

## Product boundary

Telemetry I/O can visualize the live signals an ordinary iPhone app receives, aggregate interface activity, and its own capture/output sessions. It cannot inspect every app's sensor/radio use, recover radio waveforms, or attribute all phone traffic to apps. Keep an explicit census of measured, computed, permission-needed, peer-needed, entitlement-needed, unsupported, and sample-not-yet-received channels. A demo is always marked Demo; no hardware stream receives synthetic filler.

The same distinction applies to modulation: transform values and route them to the app's audio, haptics, screen, torch, or participating network peers. These operations do not retune the phone's cellular/Wi-Fi baseband or change arbitrary radio transmit power.

Apple confirms there is no general real-time Wi-Fi/cellular signal-strength API; `NWPath.linkQuality` is a categorical alternative, not dBm. See [Apple DTS on iOS signal strength](https://developer.apple.com/forums/thread/721067).

## Radio and networking

| Signal / subsystem | Public data and implementation | Limits / activation |
| --- | --- | --- |
| Network path | `NWPathMonitor`: status, active/available interfaces, IPv4/IPv6/DNS support, expensive, constrained, ultra-constrained, and link-quality bucket. | No RF power or channel. `linkQuality` and `isUltraConstrained` are iOS 26+. Ultra-constrained alone is not proof of a particular satellite link. [NWPath](https://developer.apple.com/documentation/network/nwpath) |
| Interface receive/transmit | `getifaddrs` AF_LINK `if_data`: `ifi_ibytes`, `ifi_obytes`, `ifi_ipackets`, `ifi_opackets`; differentiate consecutive samples into B/s and packets/s. | Aggregate interface counters only; no app attribution or contents. UInt32 counters reset on reboot and wrap at 4 GiB. Interfaces may overlap; aggregate selected route interfaces rather than every tunnel/alias. No supported `if_data64` fetch. [Apple DTS interface statistics](https://developer.apple.com/forums/thread/750938) |
| This app's connection | `NWConnection` establishment and data-transfer reports: handshake/transport RTT, RTT variance, byte/packet counts, retransmissions, path interface, optional `radioType`. `URLSessionTaskMetrics` describes this app's HTTP transactions. | Measurements need an actual app connection and only describe that connection; a TCP handshake itself sends network traffic. Start probes through a visible user action. Radio type can be absent. iOS 15+ reports distinguish cellular LTE / 5G NSA or SA / sub-6 or mmWave, and Wi-Fi a/b/g/n/ac/ax. Band/channel do not follow from ax. [NWConnection](https://developer.apple.com/documentation/network/nwconnection), [URLSessionTaskMetrics](https://developer.apple.com/documentation/foundation/urlsessiontaskmetrics) |
| Cellular service | `CTTelephonyNetworkInfo.serviceCurrentRadioAccessTechnology` per reported service and `dataServiceIdentifier`. iOS 27 typed `RadioAccessTechnologyDidChangeMessage`. | No RSRP/RSRQ/SINR, dBm, cell identity, bands/ARFCN, carrier diagnostics, or baseband samples. Carrier identity APIs are deprecated without replacement. [Core Telephony](https://developer.apple.com/documentation/coretelephony/cttelephonynetworkinfo) |
| Current Wi-Fi identity | `NEHotspotNetwork.fetchCurrent`: SSID, BSSID, security type. | Requires wifi-info entitlement and precise location authorization, configuring that network, active VPN, or active DNS-settings configuration. Returned object only populates identity/security; its `signalStrength` is not a normal-app RSSI loophole. [fetchCurrent](https://developer.apple.com/documentation/networkextension/nehotspotnetwork/fetchcurrent(completionhandler:)), [Wi-Fi API overview](https://developer.apple.com/documentation/technotes/tn3111-ios-wifi-api-overview) |
| Bluetooth LE | `CBCentralManager` foreground scan, duplicates enabled: advertised RSSI in dBm, name, service/manufacturer data and Tx power when present; connected `CBPeripheral.readRSSI`. Manager power/auth state. Optional own GATT I/O. | Bluetooth permission. RSSI 127 means unavailable. Advertisers are a partial observable set, not every radio packet or every nearby device. No directional position. Background scans have different rules and duplicate delivery is suppressed. Never decode private manufacturer payloads by default. [Core Bluetooth](https://developer.apple.com/documentation/corebluetooth), [central scanning](https://developer.apple.com/documentation/corebluetooth/cbcentralmanager/scanforperipherals(withservices:options:)) |
| iBeacon | Core Location range a known `CLBeaconIdentityConstraint`: RSSI, proximity, estimated accuracy. | Needs location authorization and a matching participating beacon identifier; not a universal beacon inventory. Distance is an RF model. [CLBeacon](https://developer.apple.com/documentation/corelocation/clbeacon) |
| UWB | `NISession`: peer distance, optional direction, capability checks; peer tokens exchanged over an app-controlled link. | Participating nearby iPhone/Watch or compatible accessory required. Check all capabilities; distance/direction can be nil. Nearby Interaction permission, and camera permission only for camera assistance. This cannot scan AirTags or visualize arbitrary UWB traffic. iOS 18.4+ can range in background with a Live Activity under documented conditions. [Nearby Interaction](https://developer.apple.com/documentation/nearbyinteraction) |
| Bluetooth Channel Sounding | iOS 27 `CBCentralManager.supports(.channelSounding)`, `CBPeripheral.startChannelSoundingSession`, procedure-result distance; NI accessory configuration can use Channel Sounding. | Check runtime hardware/region support and a compatible participating peripheral. iPhone 15 Pro Max support is not promised; never infer it just from iOS 27. [WWDC26 Channel Sounding](https://developer.apple.com/videos/play/wwdc2026/369/) |
| NFC | Explicit foreground `NFCNDEFReaderSession`: successful NDEF read event, record count and format classes. Optional `NFCTagReaderSession` supports permitted tag protocols. | NFC reader entitlement and purpose string. NDEF uses entitlement value NDEF; raw tag sessions use TAG. Session UI/timeout are system controlled; this is not a passive sniffer of Apple Pay or background NFC use. Handle missing entitlement as a real error. [Core NFC](https://developer.apple.com/documentation/corenfc) |
| Wi-Fi Aware | iOS 26 `WiFiAware` + Network: paired peer connection; `WAPerformanceReport.signalStrength` (0…1), link throughput and transmit latency. | Requires wifi-aware entitlement, declared services, compatible device and pairing through system UI. This is a peer link, not the infrastructure AP's RSSI. iPhone 12+ is documented hardware support. [Wi-Fi Aware](https://developer.apple.com/documentation/wifiaware) |
| Cellular predictions | iOS 26 `WirelessInsights.ServicePredictionProvider.servicePredictions`: expected impact, start time/duration and confidence. | wireless-insights.service-predictions entitlement; handle unsupportedDevice. Predictions, not measured signal power. [WirelessInsights](https://developer.apple.com/documentation/wirelessinsights), [entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.wireless-insights.service-predictions) |
| Wi-Fi Infrastructure | iOS 26.2 accessory network credential sharing; connected AP link metadata in a permitted extension. | AccessorySetupKit pairing, secure Bluetooth transport, app + extension entitlements and sharing authorization. For end users, requires EU account and location. Not a general Wi-Fi scanner. [Wi-Fi Infrastructure](https://developer.apple.com/documentation/wifiinfrastructure) |
| Thread / Matter | ThreadNetwork credential-management APIs and permitted HomeKit/Matter accessory values. | No phone Thread spectrum/packet monitor. Accessory data describes that accessory, not hidden iPhone RF telemetry. |
| System traffic interception | A genuine VPN can use Network Extension for traffic routed through its tunnel. | Requires separate extension/capability, visible configuration consent, correct VPN product and routing. It still cannot decrypt HTTPS or inspect arbitrary RF. Apple rejects using a packet tunnel as a substitute for content-filter/DNS interception APIs. No ordinary-app per-app device-wide traffic list. [TN3120](https://developer.apple.com/documentation/technotes/tn3120-expected-use-cases-for-network-extension-packet-tunnel-providers), [deployment restrictions](https://developer.apple.com/documentation/technotes/tn3134-network-extension-provider-deployment) |

## Physical inputs and phone state

| Input | Public telemetry | Limits / permission |
| --- | --- | --- |
| Accelerometer | Raw x/y/z in g; timestamp and measured sample rate via `CMMotionManager`. | Request interval is not guaranteed hardware rate; use timestamps, show true rate and gaps. |
| Gyroscope | Raw x/y/z rotation in rad/s; processed rotation in device motion. | Same rate limits; not the physical optical gyro from Gyre's simulation. |
| Fused motion | Attitude quaternion / pitch-roll-yaw, gravity, user acceleration, calibrated magnetic field + accuracy; iOS 27 heading accuracy. | Capability-gated reference frames. Raw CMMotionManager data itself does not produce the fitness authorization prompt. Include motion usage text for the other motion APIs used. |
| Magnetometer | Raw and calibrated x/y/z µT, magnitude and field direction. | A slowly sampled magnetic sensor; no GHz RF/EM spectrum. FFT derives low-frequency content and may alias mains frequencies. |
| Pressure / altitude | `CMAltimeter`: pressure in kPa, relative altitude; supported absolute altitude, accuracy and precision. | Motion authorization and runtime availability. No public iPhone ambient-temperature/humidity probe follows from this API. |
| Steps / activity | `CMPedometer`: steps, distance, pace/cadence, floors when supported; `CMMotionActivityManager`: walking/running/cycling/automotive/stationary and confidence. | Motion & Fitness permission. Live updates are system-processed and can be sparse. [CMPedometer](https://developer.apple.com/documentation/coremotion/cmpedometer) |
| Headphone motion | `CMHeadphoneMotionManager`: connected supported headphone attitude/gravity/acceleration and connection events. | A compatible connected headphone, NSMotionUsageDescription, and runtime capability checks. [Headphone motion](https://developer.apple.com/documentation/coremotion/cmheadphonemotionmanager) |
| Location / heading | Coordinate, mean-sea-level / ellipsoid altitude, speed, course, accuracy fields, heading, source information and timestamps. | When-in-use location permission. CLLocation is fused position; it does not prove GNSS alone produced the fix. No satellite count, SNR, constellation sky view, pseudoranges or raw NMEA. [Core Location](https://developer.apple.com/documentation/corelocation) |
| Microphone | App input PCM; RMS/peak, spectral bins and dominant frequency computed from samples. | Microphone permission and audio session. dBFS is relative digital level, not calibrated SPL. No access to other apps' or calls' audio. |
| Audio I/O route | Sample rate, input/output latency, buffer duration, channels, input/output ports, output volume, interruption/route events through `AVAudioSession`. | Observes the app audio session and system route; no Bluetooth RF-quality inference. [Current route](https://developer.apple.com/documentation/avfaudio/avaudiosession/currentroute) |
| Camera / optical | Pixel frames; ISO, exposure duration, focus position, aperture, white balance/CCT. | Camera permission and explicit capture session. Luma, calculated lux and AR light intensity are estimates, not calibrated ambient-light sensor readings. [ISO](https://developer.apple.com/documentation/avfoundation/avcapturedevice/iso), [AR light estimate](https://developer.apple.com/documentation/arkit/arlightestimate) |
| LiDAR / depth | ARKit sceneDepth / smoothedSceneDepth and confidence, or supported AVFoundation depth capture. | Camera permission, supported hardware/configuration. Depth is distance data, not raw infrared detector frames or laser timing. |
| TrueDepth / face | Permitted AVFoundation depth and ARKit face geometry/blend shapes. | Explicit camera session; not Face ID template access. Do not run competing camera capture engines simultaneously. |
| Battery / charging | `UIDevice.isBatteryMonitoringEnabled`, level, state and notifications. | Unknown is a real state. No voltage/current/watts, battery health/cycles, charging temperature, or wired-vs-wireless identification. Magnetic correlation can only be marked an inference. [Battery level](https://developer.apple.com/documentation/uikit/uidevice/batterylevel) |
| Thermal / energy policy | `ProcessInfo.thermalState`, low power mode and changes. | Thermal is nominal/fair/serious/critical, not degrees Celsius. No continuous device-wide power meter. |
| Proximity | `UIDevice.isProximityMonitoringEnabled` and covered/uncovered state. | Opt-in control: enabling it can darken the screen near a face/object. No distance in metres. |
| Display | Scene's screen brightness, maximum frame rate, current display-link timing, dynamic rendering headroom where available. | Brightness is setting 0…1, not measured nits. Use `UIWindowScene.screen`, not deprecated global main access. [UIScreen](https://developer.apple.com/documentation/uikit/uiscreen) |
| Touch / control | This app's touch positions, gestures, touch force when supported, orientation and accessibility preferences. | Only events delivered to this app; no keylogger or other apps' touches. Model unsupported force explicitly. |
| App resource health | This app's frames, memory warnings and optional process metrics. iOS 27 MetricKit `MetricManager` async reports include CPU, memory, network and disk metrics. | MetricKit is real-device, delayed/report-based telemetry for this app. No live per-app system process list. [MetricKit reporting](https://developer.apple.com/documentation/metrickit/monitoring-app-performance-with-metrickit) |
| Research sensors | SensorKit can provide approved study data including ambient light and usage reports. | Requires Apple approval, research entitlement, authorization and delayed samples. Exclude from normal-app live claims. [SensorKit](https://developer.apple.com/documentation/sensorkit) |
| External accessories | Supported protocol messages, audio/camera routes, game-controller inputs, HomeKit values, WatchConnectivity peer messages. | Permission, protocol, pairing and/or manufacturer support as appropriate. No arbitrary USB bus analyzer or Bluetooth Classic packet sniffing. [External Accessory](https://developer.apple.com/documentation/externalaccessory) |

Motion framework reference: [Core Motion](https://developer.apple.com/documentation/coremotion). All sources report actual availability, delivery timestamps, permission state and measured rate independently. A function being linkable in the SDK does not guarantee the phone has a sensor. In particular, CMBatchedSensorManager's watch-oriented 800 Hz examples must not become an iPhone sample-rate promise.

## Outputs and modulation

- **Screen:** live plot geometry, color, trail/timebase, gain/bias/smoothing/deadband and threshold mapping; optional explicitly enabled display brightness, restoring the prior setting when the mapping ends.
- **Audio:** `AVAudioSourceNode` synthesizes the app's oscillator; map normalized signal to pitch/amplitude with bounded gain, start/stop and route handling. Acoustic output is not RF transmission.
- **Haptics:** `CHHapticEngine` or SwiftUI sensory feedback for meaningful threshold crossings/gestures; runtime support, cooldown and intensity limits. [Preparing haptics](https://developer.apple.com/documentation/corehaptics/preparing-your-app-to-play-haptics)
- **Torch:** explicit camera-authorized `AVCaptureDevice.setTorchModeOn(level:)`; hardware/thermal availability, low default level, switch off on stop/background. Do not race an existing camera session.
- **Peer data:** app-controlled BLE GATT or Network/Wi-Fi Aware messages to a participating peer, separate from diagnostic receive-only mode. No arbitrary cellular carrier, Wi-Fi channel, NFC field power or UWB waveform control.

## Local corpus and signing

Spectra already has useful patterns at `Spectra/Spectra/Live/Sources`: source ownership, per-channel permission/availability, timestamped rings, sensor census and per-stream Live/Computed/Model/Demo provenance. Its radio link report and BLE RSSI implementations are good starting points. Its NFC and UWB channels currently show constraints/model data; those are not working general readers or paired ranging sessions. Gyre's `RadioSense` turns real BLE/magnetic inputs into visual/haptic forces, and explicitly treats unmeasured directions as symbolic.

Current cached team capabilities were read on 2026-10-11: the team cache has 11 capabilities and does not list NFC Tag Reading, Access Wi-Fi Information, Wi-Fi Aware, SensorKit, Network Extensions, Wi-Fi Infrastructure, or WirelessInsights. The installed portal capability definitions exclude the free-program team type for those features. This is a cached local signing fact, not a fresh account-portal assertion. A signed build must verify its own provisioning profile; source imports and `readingAvailable` alone do not prove entitlement eligibility. See [supported capabilities](https://developer.apple.com/help/account/reference/supported-capabilities-ios).

The supplementary services `InterfaceTraffic.swift`, `NFCProbe.swift` and `NearbyProbe.swift` passed Swift 6 type-checking against the installed iOS 27 SDK. Counter arithmetic lives in `TelemetryCore.TrafficMath`; its seven dedicated wrap/reset/gap tests passed as part of the 13-test core suite. A separate Mac sampler check verified the route-name filter and first-sample behavior. These checks establish source/API correctness; physical interface reporting, an entitled NDEF tag read and an actual two-phone UWB range remain separate device scenarios.

## Supplementary implementation verification

- Interface traffic uses current route interface names when supplied, excludes common tunnel/peer aliases, rebaselines resets across companion counters, and never claims persistent/per-app totals.
- NFC reads only user-started foreground NDEF sessions. It retains record counts and format classes, and gives an actionable error if the provisioning profile lacks its entitlement. Before starting it checks the bundled `NFCReaderUsageDescription`: Apple documents that an absent purpose string exits the process. The public iOS 27 `NFCNDEFReaderSession.h` explicitly specifies that a missing reader entitlement instead delivers `NFCReaderErrorSecurityViolation` to the invalidation delegate, which this service handles. No private entitlement-inspection APIs or provisioning-profile parsing are used. [NFC reader setup](https://developer.apple.com/documentation/corenfc/building-an-nfc-tag-reader-app), [purpose string](https://developer.apple.com/documentation/bundleresources/information-property-list/nfcreaderusagedescription).
- Default signing omits NFC capability. An eligible paid team can enable NFC Tag Reading in its App ID/profile and build with `CODE_SIGN_ENTITLEMENTS=TelemetryIO/NFC.entitlements`, the supplied optional file containing the `NDEF` format. For example, append that setting to the normal `xcodebuild -project TelemetryIO.xcodeproj -scheme TelemetryIO -destination 'generic/platform=iOS' -allowProvisioningUpdates build` command. This setting alone cannot grant a capability absent from the signing profile.
- UWB distance and X/Y/Z direction components use only actual Nearby Interaction samples from a consenting token-exchanged peer. Direction components describe the unit vector relative to the phone's frame and stay absent when the framework does not supply direction.
- Nearby Interaction uses manual exchange of securely archived, base64 discovery tokens. The reader limits archive size and admits only `NIDiscoveryToken`, rejects the local token as a peer, clears measurements during suspension/removal/invalidation, and never substitutes an estimated RSSI range. Both participating phones must prepare, exchange tokens and run a peer session. Camera assistance and background ranging are not enabled in this implementation.
